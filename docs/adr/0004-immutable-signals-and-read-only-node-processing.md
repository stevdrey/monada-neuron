# ADR 0004: Immutable Signals and Read-Only Node Processing

## Status

Accepted

## Context

Monada Neuron requires an executable contract for presenting structured information to a Node and receiving explicit output. Signals are expected to be created and processed frequently, while Nodes already have durable UUID identity and mutable frequency/energy state.

The first contract must provide correlation, typed classification, deterministic value semantics, and ordered multi-output behavior without introducing modality frameworks, generic payload maps, hidden global emission state, or accidental node mutation.

## Decision

`Signal` is an immutable record containing a caller-assigned UUID, a `SignalKind`, and a `FrequencyState`.

The UUID is required and is never generated by the Signal model. It supports correlation and tracing during cognitive execution but does not imply persistence. Producers own UUID creation and any uniqueness guarantee required by their flow. Signal equality and hashing remain structural across all record components.

`SignalKind` classifies cognitive role as observation, intermediate processing data, or feedback. It does not classify text, audio, image, provider, or storage formats.

Signal intensity is represented by `FrequencyState.amplitude`. Signal does not add energy or sequence fields. Node energy remains node activation state, and future cycle context may own ordered trace sequence metadata independently of the Signal value.

`Node` implements a read-only `NodeView` exposing only identity, type, current frequency state, and energy. `NodeProcessor` accepts this view plus one Signal and returns a `NodeProcessingResult`. Processing does not mutate the Node. Node transitions and adaptive updates remain separate explicit operations.

`NodeProcessingResult` snapshots an ordered list of emitted signals. List order is the observable output order, duplicates are retained, and an empty result means successful processing with no output. Failures propagate to the caller and are not converted to empty output.

## Alternatives Considered

### Use no Signal identifier

Rejected because explicit correlation and trace identity are required for the initial Signal contract.

### Use a compact numeric sequence

Rejected for this initial API in favor of caller-controlled UUID correlation. This accepts the UUID allocation and footprint cost. A future data-oriented execution backend may use compact internal identifiers behind the domain contract if measurements justify it.

### Generate UUIDs inside Signal

Rejected because implicit randomness would hide allocation and make deterministic fixtures and replay harder to control.

### Add Signal energy or generic metadata/payload maps

Rejected because energy would overlap frequency amplitude or Node activation, while generic maps would weaken typing and introduce avoidable allocation and provider leakage.

### Allow NodeProcessor to mutate Node directly

Rejected because processing output and state adaptation would become coupled and harder to observe, replay, or evaluate independently.

## Consequences

- Every Signal producer must supply a UUID explicitly.
- Signal allocation includes UUID storage; high-volume workloads must measure this cost before introducing an alternative internal representation.
- Signal values remain immutable, modality-neutral, and independent from external providers and Monada Resonance Store types.
- Node-processing output has deterministic list ordering and explicit zero-output behavior.
- Processing cannot update Node state through its declared view; adaptation remains an explicit later boundary.
- A later runtime may attach cycle-local sequence or trace metadata without changing Signal's current value contract.

## Follow-Up

The deterministic propagation runtime should preserve emitted list order and assign any traversal or trace sequencing outside Signal. Performance evaluation should measure Signal/UUID allocation before selecting compact identifiers or layouts, and any optimized representation must preserve this reference behavior.
